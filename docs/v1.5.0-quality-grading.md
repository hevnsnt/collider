## Team Plan: Bring All Non-A Items to A

Ranked by impact × effort. Each item lists target grade A, work, and effort (S/M/L = hours/days/week+).

### CRITICAL (block v1.5.0 release polish)

#### TP-1. Settings Panel Live-Apply Backend Wiring — C → A (M)
**Owner**: backend-engineer
**Why critical**: Phase D ships a UI that does nothing yet. Operators will edit settings, see dirty flags, and observe zero behavioral change. That's broken UX masquerading as a feature.
**Work**:
1. In `pool_solver.cpp` `cb.on_progress`, after the existing TUI bridge add:
   ```cpp
   if (pool_tui && settings_state) {
       auto snap = panels::snapshot_and_clear(*settings_state);
       if (snap.dirty.backend_kind) { /* TODO log: deferred until next chunk */ }
       if (snap.dirty.refresh_hz) { /* pass to TuiApp setter */ }
       if (snap.restart_requested) { restart_pending.store(true); }
   }
   ```
2. Same pattern in `puzzle_solver_kangaroo.cpp` (both RCKangaroo + MultiGPU progress callbacks).
3. Same in `brain_wallet_runner.cpp`'s between-batch tick.
4. Add TuiApp::set_refresh_hz() so theme-cycle ticks live-apply.
5. Test: `test_settings_live_apply.cpp` — single mode integration test.
**Acceptance**: `o` opens settings; edits to refresh_hz visibly change frame cadence within 1s; backend change latches restart in pool mode.

#### TP-2. Wordlist Composer dispatch_composer_action Verification — B → A (S)
**Owner**: backend-engineer
**Why**: Audit flagged it as missing; my prior commit (74cb29e) did implement it. Verify it actually invokes the recombine + PCFG paths end-to-end.

2. Add `test_wordlist_composer.cpp`: invoke Recombine action, assert sorted output, assert AsyncSlot.done flips true.
3. Add `test_wordlist_composer_pcfg.cpp`: invoke PCFG retrain, assert grammar file is written.

### HIGH (improve confidence before any production deployment)

#### TP-3. BIP-32 Test Coverage — C+ → A (M)
**Owner**: quality-engineer
**Why**: New cryptographic code (bip32.hpp) has zero dedicated test coverage. Production keys derive through this code.
**Work**:
1. Create `tests/test_bip32_kat.cpp` with the standard BIP-32 test vectors (the 5 in the spec).
2. Add test for `parse_path()` edge cases (hardened, mixed, malformed).
3. Add test for `add_mod_n()` with operands near n.
4. Add `test_bip39_seed_kat.cpp` with the BIP-39 test vectors (12 vectors in the spec).
**Acceptance**: All vectors round-trip; cmake ctest registers the targets; CI runs them on every push.

#### TP-4. BIP Scanner Error Visibility — B → A (S)
**Owner**: backend-engineer
**Why**: Silent exception swallowing in derivation loop hides real problems.
**Work**:
1. Track counters: `derivation_errors_invalid_il`, `derivation_errors_zero_key`, `pubkey_errors`. Surface in summary stats.
2. Add tight-bloom secondary probe (mirror brainwallet path) so BIP scanner reports fewer FP.
3. Tracking ticket for BIP-86 Taproot path + bloom indexing rework.
**Acceptance**: Summary shows non-zero counters when running against intentionally-bad mnemonics; tight bloom reduces false positives by >90% on test corpus.

#### TP-5. GPU Fused Pipeline OOB + Exception Audit — B → A (L)
**Owner**: security-auditor + glv-decompose-debugger
**Why**: GPU kernels can fault with `cudaErrorIllegalAddress` and lose hours of work. v1.4.x ad5326d already fixed one OOB; need full audit.
**Work**:
1. Audit `src/gpu/fused_pipeline.cu` and `src/gpu/v2/brain_wallet_v2.cu` for kernel-side bounds checks on every buffer access.
2. Audit warp-divergence handling when one lane hits an invalid scalar.
3. Add `test_fused_pipeline_oob.cu` exercising boundary inputs (max batch, near-zero scalars, malformed pubkeys).
4. Add CUDA_LAUNCH_BLOCKING wrapper for diagnostic builds.
**Acceptance**: OOB test green; production runs survive 24+ hours without `cudaErrorIllegalAddress`.

#### TP-6. State Persistence Atomic-Write KAT — B- → A (M)
**Owner**: quality-engineer
**Why**: Brainwallet/kangaroo state files are recovery-critical. Corruption on crash mid-write loses hours of work.
**Work**:
1. Create `tests/test_state_atomic_write.cpp` that kills the process at every byte offset during save and verifies the recovered state.
2. Add fsync barrier confirmation (Windows _commit + POSIX fsync).
3. Verify .tmp cleanup on partial-write failure.
**Acceptance**: Test runs ~1000 mid-write kills, all recoveries land on the previous good state or detect corruption explicitly.
